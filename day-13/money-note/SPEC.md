# Money Note 記帳小工具 — 規格書

> 版本：v1（MVP）
> 日期：2026-08-07

---

## 1. 這個東西要解決什麼

一個人用的記帳工具。核心問題只有一個：**我的錢到底花去哪了。**

主要情境是「花完錢的當下，站在超商門口拿手機記一筆」。所以速度比功能多寡重要 —
記一筆的路徑必須短到不會讓人懶得記。記不成，後面所有報表都是空的。

## 2. 使用者

只有作者本人。**不做註冊、不做登入、不做多人共用。**
資料存在自己的瀏覽器裡，不上傳任何伺服器。

## 3. 範圍

### 做

- 新增一筆支出
- 編輯已記錄的支出
- 刪除已記錄的支出
- 切換月份，看該月的總支出
- 一鍵回到本月
- 看該月的流水清單
- 切到統計頁，看該月的總支出、記帳筆數與分類佔比圓餅圖

### 不做（v1 明確排除）

| 不做的事 | 原因 |
|---|---|
| 記錄收入 | 只回答「錢花去哪」，不做資產負債 |
| 帳戶 / 付款方式 | 一加就會延伸出「各帳戶餘額」，MVP 撐不住 |
| 預算與超支提醒 | 先讓人記得住帳，再談控制 |
| 跨月趨勢圖 | 沒有幾個月的資料前沒有意義 |
| 分類的新增 / 刪除 / 改名 | 內建固定幾組就夠，省掉一整個管理介面 |
| 帳號、雲端同步、多裝置 | 單人單機 |

## 4. 資料模型

一筆記錄：

```js
{
  id:        "3f1c...",      // crypto.randomUUID()
  amount:    120,            // 正整數，新台幣，不收小數與負數
  category:  "food",         // 見下方分類清單
  date:      "2026-08-07",   // YYYY-MM-DD（當地時間，非 UTC），使用者選的消費日
  note:      "全家咖啡",      // 選填，可為空字串
  createdAt: 1786077000000   // Date.now()，按下存檔的當下
                             // 此例 = 2026-08-07 12:30（UTC+8），與 date 同一天
}
```

`date` 與 `createdAt` 可以不同天 —— 補記昨天的帳時，`date` 是昨天、`createdAt` 是今天。
**判斷一筆屬於哪個月，一律看 `date`，不看 `createdAt`。**
`createdAt` 只用於同日排序。

### 分類（寫死在程式碼常數）

| id | 顯示名稱 |
|---|---|
| `food` | 飲食 |
| `transport` | 交通 |
| `daily` | 日用 |
| `entertainment` | 娛樂 |
| `medical` | 醫療 |
| `other` | 其他 |

不夠用的時候直接改常數檔加一組即可 —— 但既有記錄的 `category` 是靠 id 對應，
**已經用過的 id 不可以刪除或改名**，否則舊資料會對不到分類。

### 儲存

- 位置：`localStorage`
- Key：`money-note:records:v1`
- 格式：整個陣列序列化成一個 JSON 字串
- 讀取時若 `JSON.parse` 失敗，視為空陣列，不要讓整個 app 掛掉

Key 帶 `v1` 是為了將來資料結構改動時能做遷移判斷。

## 5. 畫面

兩個分頁加一個表單，**不裝 Vue Router** —— 目前在哪一頁是 `App.vue` 的一個 `ref`。

月份切換列在兩個分頁之上、兩頁共用，切分頁不會重置月份。

### 5.1 記帳頁

```
┌─────────────────────────────┐
│  ◀   2026-08   ▶    [本月]  │  月份切換（兩頁共用）
│  本月支出  $12,480           │
├─────────────────────────────┤
│  08/07  飲食  全家咖啡   $60 │
│  08/07  交通  捷運       $32 │
│  08/06  飲食  中午便當  $110 │
│      …                       │
├─────────────────────────────┤        [ ＋ ]
│    記帳     │     統計       │  底部分頁
└─────────────────────────────┘
```

**月份切換**

- 預設顯示當月
- `◀` `▶` 切換上／下個月
- 不限制可切到多久以前或以後
- 因為切換無上下限，另放一顆「本月」按鈕，一次點擊直接跳回當前月份，
  不用連按箭頭往回數
- 「本月」依當地時間的今天所在月份判定，與 `date` 欄位的時區規則一致
- 目前檢視的就是本月時，該按鈕隱藏但保留版面空間，避免左右箭頭跳位

**本月總支出**

- 該月所有記錄的 `amount` 加總
- 千分位逗號，前面加 `$`

**流水清單**

- 依日期新到舊排序，同一天再依 `createdAt` 新到舊
- 每列顯示：日期（MM/DD）、分類、備註、金額
- 點一列 → 開啟編輯表單，帶入原本的值
- 清單列本身不放刪除鈕，刪除入口在編輯表單裡（見 5.3）

**空狀態**

- 該月一筆都沒有時，清單不顯示
- 改顯示一句提示與新增按鈕，不要留一片空白

**新增按鈕**

- 右下角固定浮動按鈕，單手拇指按得到
- 位置要墊過底部分頁列，不能壓在「記帳／統計」上
- **只在記帳頁出現**：在統計頁按 ＋ 記完帳，畫面停在統計頁上會讓人以為沒存進去

### 5.2 新增 / 編輯表單

新增與編輯共用同一個表單元件，以 bottom sheet 由下往上出現。

```
金額   [  120  ]          ← 自動聚焦，數字鍵盤
分類   [飲食][交通][日用][娛樂][醫療][其他]
日期   [2026-08-07]       ← 預設今天
備註   [ 全家咖啡      ]   （選填）
           [ 存檔 ]
```

**欄位規則**

| 欄位 | 必填 | 預設 | 規則 |
|---|---|---|---|
| 金額 | 是 | 空 | 正整數，須 > 0 |
| 分類 | 是 | 無 | 六選一，用按鈕不用下拉選單 |
| 日期 | 是 | 今天 | 原生 `<input type="date">` |
| 備註 | 否 | 空 | 單行文字，上限 50 字 |

**輸入細節（直接影響「三秒記完」）**

- 開啟時游標自動落在金額欄
- 金額欄使用 `inputmode="numeric"`，手機直接跳數字鍵盤
- 分類做成一排可點的按鈕，不要 `<select>` —— 少一次展開收合
- 存檔後表單關閉，清單即時更新
- 金額為空或為 0 時，存檔按鈕維持禁用狀態，不要按下去才跳錯誤

**編輯時**

- 標題改為「編輯」，各欄位帶入原值
- 存檔後保留原 `id` 與 `createdAt`，只更新內容
- 若把日期改到別的月份，該筆會從當前檢視的月份消失，這是預期行為
- 表單底部提供刪除入口，只在編輯模式出現（見 5.3）

### 5.3 刪除

- 刪除入口在編輯表單內，只在編輯模式出現；清單每列不放刪除鈕
- 路徑是「點該列 → 開啟編輯表單 → 刪除」，開表單這一步本身就是一道緩衝
- **刪除前需二次確認**，避免手機誤觸。確認就地展開，不用 `window.confirm()`
- 確認後表單關閉，該筆同時從清單與統計消失
- 不做垃圾桶、不做復原

### 5.4 統計頁

```
┌─────────────────────────────┐
│  ◀   2026-08   ▶    [本月]  │  月份切換（兩頁共用）
│  本月支出  $12,480           │
├─────────────────────────────┤
│  ┌──────────┐ ┌──────────┐  │
│  │ 本月支出  │ │ 記帳筆數  │  │
│  │ $12,480  │ │  12 筆    │  │
│  └──────────┘ └──────────┘  │
├─────────────────────────────┤
│           ╭───────╮          │
│          │  圓餅圖 │         │
│           ╰───────╯          │
│  ● 飲食         $5,200  42%  │
│  ● 交通         $2,800  22%  │
│  ● 日用         $2,300  18%  │
├─────────────────────────────┤
│    記帳     │     統計       │
└─────────────────────────────┘
```

**統計數字**

- 顯示的一律是「當前檢視月份」的資料，不是永遠的本月 —— 切到三月看記帳、
  切過去統計也還是三月
- 總支出與上方月份切換列重複顯示：上面那個是切月份時的即時回饋，
  這裡是跟筆數並列的統計數字，兩者層級不同
- 切到非本月時，卡片標題同樣由「本月支出」改成「當月支出」，與 5.1 同一條規則

**分類佔比**

- 圓餅圖（甜甜圈）＋ 下方文字明細，**兩者同時顯示**
- 明細每列有：色塊、分類名稱、金額、百分比。**不能只靠顏色辨識** ——
  canvas 讀不出來，色覺障礙也看不出差別，顏色純粹是輔助
- 依金額由大到小排序，金額相同時退回 `CATEGORIES` 的宣告順序
- 該月沒花到的分類不顯示，不要列一排 0
- 百分比四捨五入到整數；不強求加總剛好 100%
- 統計的計算邏輯放在 `src/utils/stats.js` 的純函式裡，不跟畫面或儲存綁在一起

**空狀態**

- 該月一筆都沒有時，總支出顯示 `$0`、筆數顯示 `0 筆`
- 圓餅圖整塊不顯示，改顯示一句提示 —— 空資料丟給 Chart.js 會畫出一個
  沒有任何扇形的空白圓，看起來像壞掉

## 6. 技術決定

| 項目 | 選擇 | 理由 |
|---|---|---|
| 框架 | Vue 3 + Vite | 用 `<script setup>` Composition API |
| 路由 | 不裝 | 只有兩個分頁，用一個 `ref` 切換；表單用 bottom sheet |
| 狀態管理 | 不裝 Pinia | 一個 composable 就夠了 |
| 樣式 | Tailwind CSS | 手機優先，直接寫在 template 上 |
| 圖表 | Chart.js + vue-chartjs | 統計頁的圓餅圖。見第 10 節 2026-08-16 那列 |
| 日期處理 | 原生 `Date` | 只做「取月份」「格式化」，不需要 day.js |

### 建議檔案結構

```
src/
├─ App.vue                    # 版面組裝、分頁切換
├─ main.js
├─ constants/
│  └─ categories.js           # 分類清單（唯一真實來源），含圓餅圖用的顏色
├─ composables/
│  └─ useRecords.js           # 讀寫 localStorage、CRUD、月份篩選
├─ utils/
│  ├─ format.js               # 金額與日期格式化、「今天」「本月」的取值
│  └─ stats.js                # 統計計算（純函式）
└─ components/
   ├─ MonthSwitcher.vue       # 月份切換 + 該月總額
   ├─ RecordList.vue          # 流水清單
   ├─ RecordForm.vue          # 新增 / 編輯 bottom sheet
   ├─ TabBar.vue              # 底部分頁
   ├─ StatsPanel.vue          # 統計頁內容
   └─ CategoryPieChart.vue    # 分類佔比圓餅圖 + 文字明細
```

`useRecords.js` 是唯一碰 `localStorage` 的地方。元件不直接讀寫。

`stats.js` 是純函式：吃一個記錄陣列、回傳結果，不碰 `localStorage`、不碰 Vue 的 `ref`。
要算哪一段（哪個月）是 `useRecords.js` 的事，怎麼算是 `stats.js` 的事。

### 響應式

以 375px 寬（iPhone SE）為設計基準。桌機開啟時內容置中、限制最大寬度即可，
不另外設計桌機版面。

## 7. 驗收條件

v1 完成的定義：

1. 手機開啟，按右下角按鈕 → 輸入 120 → 點「飲食」→ 存檔，三個動作內記完一筆
2. 新記的那筆立刻出現在清單最上方，本月總額同步增加
3. 圓餅圖的扇形大小與明細的百分比正確反映該月各分類金額
4. 點清單任一列可以修改金額／分類／日期／備註，存檔後清單與統計同步更新
5. 刪除會先跳確認，確認後該筆從清單與統計中消失
6. 重新整理頁面，所有資料還在
7. 切到沒有記錄的月份，顯示空狀態而不是壞掉的圖表
8. 把某筆的日期改成上個月，該筆會從本月消失、出現在上個月
9. 連按 `◀` 切到數個月前，點一次「本月」即回到當前月份；此時「本月」按鈕消失，
   且月份切換列的左右箭頭位置不位移
10. **新增一筆支出後切到統計頁，總支出、記帳筆數與圓餅圖都反映最新資料**
11. 在統計頁切換月份，三個數字與圓餅圖同步換成該月；切分頁不會把月份重置回本月

## 9. 之後可能長出來的東西

先寫在這裡，讓 v1 的實作不要把路堵死：

| 未來需求 | 現在該預留什麼 |
|---|---|
| 記錄收入 | 每筆加一個 `type: 'expense' \| 'income'` 欄位。v1 不加此欄，改動時走 localStorage key 版本升級（`v1` → `v2`）並寫遷移函式 |
| 每月預算 | 需要一個獨立的設定儲存區，與記錄陣列分開存 |
| 跨月趨勢 | 現有資料結構已足夠，純粹是多一個統計畫面 |
| 分類自訂 | 分類已用 id 而非顯示名稱儲存，將來改成可編輯不會動到舊資料 |
| 雲端同步 | `useRecords.js` 是唯一的資料存取層，抽換成 API 呼叫時元件不用動 |

記下已經拍板的結論與理由，避免日後重新爭論同一件事。

| 日期 | 決策 | 理由 |
|---|---|---|
| 2026-08-07 | 月份切換加一顆「回到本月」按鈕，列入 v1 範圍 | 月份切換不設上下限，切遠了要連按幾十次箭頭才回得來 |
| 2026-08-07 | 目前檢視就是本月時，該按鈕隱藏但保留版面空間 | 與「該月沒花到的分類不顯示」同一取向；保留空間是為了避免左右箭頭跳位 |
| 2026-08-07 | 「本月」依當地時間的今天判定，不用 UTC | 與 `date` 欄位既有的時區規則一致 |
| 2026-08-07 | 修正資料模型範例的 `createdAt`，改成與 `date` 同一天的時間戳 | 原值換算是 2025-08-07，與 `date: "2026-08-07"` 差一年。這是全文唯一一筆範例資料，被照抄成測試資料會產生時間錯亂的紀錄，也會讓同日排序的測試看似通過、實際沒驗到 |
| 2026-08-07 | 明定「判斷月份一律看 `date`，`createdAt` 只用於同日排序」 | 兩個時間欄位的分工原本沒寫，是上面那個範例會寫錯的根因 |
| 2026-08-09 | 技術選型維持第 6 節原案（Vue 3 + Vite + Tailwind），不改用純 HTML 或 React | 與純 HTML 單檔、React 兩個方案比較後確認。純 HTML 省掉 build，代價是畫面各處同步要手刻，而驗收條件有一半在考同步；React 的優勢在此規格用不到。完整比較見 [TECH_CHOICE.md](./TECH_CHOICE.md) |
| 2026-08-09 | 新增 `src/utils/format.js`，第 6 節的建議檔案結構多一個 `utils/` 目錄 | 金額千分位與 `MM/DD` 在總額與清單兩處都要用，寫在各自元件裡會有兩份、改一邊忘一邊。順帶把「今天」「本月」的取值也收進同一個檔，讓「用當地時間不用 UTC」這條規則只存在一個地方 |
| 2026-08-09 | 存檔按鈕的禁用條件補上「未選分類」，不只第 5.2 節寫的「金額為空或 0」 | 分類同樣是必填且沒有預設值，只擋金額的話按得下去、會存出 `category` 為空的記錄 |
| 2026-08-09 | id 產生改為 `crypto.randomUUID?.() ?? 時間戳＋亂數`，不直接呼叫 `crypto.randomUUID()` | `crypto.randomUUID` 只在 secure context 有值。手機實機測試走 `npm run dev -- --host` 是 http，直接呼叫會在按下存檔時 throw —— 而且桌機 localhost 完全正常，只有手機上壞 |
| 2026-08-14 | 分類佔比金額相同時，退回 `CATEGORIES` 的宣告順序排列 | 第 5.1 節只寫「依金額由大到小」，平手時沒有規則，順序會跟著記錄的輸入順序漂移，同一份資料重整前後可能換位。三個分類各記一筆同額是很容易碰到的情境 |
